# Объяснение для руководителя (без технических терминов)

## Как устроена система

Это простая программа для постановки и контроля задач по стройкам. Есть две роли.

- **Руководитель (постановщик)** — заводит объекты, создаёт задачи, назначает исполнителей и принимает или возвращает работу.
- **Исполнитель** — видит только свои задачи: берёт их в работу, отправляет на проверку.

У каждой задачи есть статус — «новая», «в работе», «на проверке», «принята», «на доработке». Если руководитель возвращает задачу, он **обязан написать комментарий** — почему.

Все перемещения задачи автоматически записываются в журнал: кто, когда и что сделал. Спорные ситуации легко восстановить по этому журналу.

## Как защищены данные

- Вход в систему — только по **личному логину и паролю**.
- Самостоятельно зарегистрироваться **нельзя**: учётные записи заводит администратор, так что чужих людей в системе нет.
- Все правила доступа встроены **в саму базу данных**, а не только в интерфейс программы. Это значит: даже если кто-то попытается обойти экран программы и «достать» данные напрямую, база всё равно не отдаст ему чужую информацию — проверка срабатывает на самом нижнем уровне.

## Что не может сделать исполнитель

- **Увидеть чужие задачи** или объекты, где у него нет работы — база их просто не покажет.
- **Взять в работу чужую задачу** или изменить статус задачи, которая не его.
- **«Принять» свою же работу** или перевести задачу в статус, который по порядку не положен — база разрешает только правильную последовательность шагов.
- **Исправить, удалить или подделать запись в журнале истории** — журнал можно только читать. Ни у кого из пользователей, включая постановщика, таких прав нет.
- **Удалять или редактировать задачи и объекты** — это право есть только у постановщика.

> **Коротко:** исполнитель ограничен своей ролью на уровне хранилища данных, обойти ограничения нельзя ни через программу, ни в обход неё, а вся история действий защищена от изменений.
